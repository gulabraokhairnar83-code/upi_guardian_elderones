# UPI Guardian — MongoDB Database Specification & Data Privacy Model

**Database Engine**: MongoDB Atlas (v7.0+) / mongomock fallback  
**Database Name**: `upi_guardian_prod` (Production) / `upi_guardian_dev` (Development)  
**Schema Model**: Document-oriented with JSON Schema application validation  

---

## 1. Overview & Data Minimization Principles

UPI Guardian enforces strict **privacy-by-design** and data minimization principles:
- **No Direct Banking Credentials**: OTPs, UPI PINs, net banking passwords, CVVs, and complete 16-digit debit card numbers are **never stored, transmitted, or requested**.
- **Password Hashes**: User passwords are encrypted using salted `scrypt`/`pbkdf2` algorithms before insertion.
- **Telecom Privacy**: User and caregiver phone numbers are stored with country codes for notification delivery, but masked in user interfaces (`+91 98765 ****`) and stripped from public telemetry endpoints.
- **Message Content Privacy**: Message analysis persists the raw communication text only for user review history; sensitive financial account numbers in transcripts are scrubbed during vectorization.

## 2. Collection Specifications

### 2.1 `users`
- **Purpose**: Stores registered elder and caregiver account profiles and authentication state.
- **Key Fields**:
  - `user_id` (string, unique): Primary application identifier (e.g., `usr_sunita_68`).
  - `name` (string): Full name of the user.
  - `email` (string, unique): Normalized lowercase email address.
  - `phone` (string, optional): Contact telephone number.
  - `password_hash` (string): Salted Werkzeug password hash. Never returned in API responses.
  - `role` (string): User role (`ELDER` or `CAREGIVER`).
  - `is_active` (boolean): Account activation status; deactivated users cannot authenticate.
  - `created_at` (string ISO): Account creation timestamp.
- **Indexes**:
  - `user_id` (unique, sparse)
  - `email` (unique, sparse)
  - `phone` (sparse)
- **Relationships**: Parent record referenced by `transactions.user_id`, `caregivers.elder_user_id`, `alerts.user_id`, `risk_events.user_id`.

---

### 2.2 `transactions`
- **Purpose**: Records incoming payment requests and evaluated transaction history.
- **Key Fields**:
  - `id` (string, unique): Unique transaction identifier (e.g., `TXN-UG-928401`).
  - `user_id` (string): Identifier of the executing elder user.
  - `payee` (string): Name or handle of the receiving merchant/individual.
  - `amount` (float): Transaction value in Indian Rupees (INR). Capped at ₹10,000,000.
  - `upi_id` (string): Virtual Payment Address (VPA) of payee (e.g., `payee@okaxis`).
  - `timestamp` (string ISO): Transaction initiation timestamp.
  - `status` (string): Evaluation state (`COMPLETED`, `FLAGGED`, `PENDING_REVIEW`).
  - `risk_score` (float): Anomaly score from Isolation Forest.
  - `risk_level` (string): Categorization (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
  - `is_new_payee` (boolean): True if payee has not been previously transacted with.
- **Indexes**:
  - `id` (unique)
  - `user_id`
  - Compound: `(user_id: 1, timestamp: -1)` (optimized for user timeline feeds)
  - `status`
  - `payee`

---

### 2.3 `alerts`
- **Purpose**: Stores actionable risk alerts displayed on the elder's dashboard and alerts page.
- **Key Fields**:
  - `id` (string, unique): Alert identifier (e.g., `ALT-9281`).
  - `user_id` (string): Target elder user identifier.
  - `transaction_id` (string, optional): Associated transaction reference.
  - `title` (string): Clear advisory title (e.g., `Unusual payment request flagged`).
  - `description` (string): Plain-language explanation of risk factors.
  - `level` (string): Severity level (`review`, `high`, `critical`).
  - `status` (string): Alert resolution state (`ACTIVE`, `RESOLVED`, `DISMISSED`).
  - `timestamp` (string ISO): Generation timestamp.
- **Indexes**:
  - `id` (unique)
  - `user_id`
  - `level`
  - `status`

---

### 2.4 `analyzed_messages`
- **Purpose**: Stores historical analysis of SMS communications and digitized phone call transcripts.
- **Key Fields**:
  - `id` (string, unique): Message analysis record ID.
  - `user_id` (string): Elder user receiving the communication.
  - `text` (string): Scanned text content. Capped at 5,000 characters.
  - `message_type` (string): Type discriminator (`sms` or `call_transcript`).
  - `is_scam` (boolean): Binary classification prediction.
  - `confidence` (float): Calibrated probability score ($0.0-1.0$).
  - `risk_level` (string): Risk tier (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
  - `indicators` (array of strings): Detected scam keywords (e.g., `["urgent", "kyc_expired", "lottery"]`).
  - `analyzed_at` (string ISO): Analysis timestamp.
- **Indexes**:
  - `user_id`
  - `analyzed_at`
  - `type`

---

### 2.5 `risk_events`
- **Purpose**: Immutable audit log of multi-signal fused risk assessments generated by the Risk Fusion Engine.
- **Key Fields**:
  - `event_id` (string, unique): Risk event identifier.
  - `user_id` (string): Target elder user.
  - `transaction_id` (string, optional): Associated transaction.
  - `communication_id` (string, optional): Correlated communication ID.
  - `final_risk_score` (float): Composite fused score ($0.0-100.0$).
  - `risk_level` (string): Fused classification (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
  - `temporal_correlation_applied` (boolean): True if +10 correlation boost was triggered.
  - `risk_factors` (array of strings): Human-readable explanatory factors.
  - `recommended_action` (string): Specific advice for the senior user.
  - `timestamp` (string ISO): Evaluation timestamp.
- **Indexes**:
  - `user_id`
  - `timestamp`

---

### 2.6 `caregivers`
- **Purpose**: Maintains designated caregiver relationships, contact channels, and verification states.
- **Key Fields**:
  - `caregiver_id` (string, unique): Caregiver relationship identifier (e.g., `cg_88e1ace315`).
  - `elder_user_id` (string): ID of the elder who nominated this caregiver.
  - `caregiver_user_id` (string, optional): Associated registered caregiver user account.
  - `name` (string): Caregiver full name.
  - `phone` (string): Contact telephone number.
  - `email` (string): Contact email address.
  - `relationship` (string): `SON`, `DAUGHTER`, `SPOUSE`, `RELATIVE`, `FRIEND`, or `OTHER`.
  - `is_verified` (boolean): Verification state.
  - `is_active` (boolean): Active status flag.
  - `notification_preferences` (object): Configured delivery channels (`sms_enabled`, `voice_enabled`, `quiet_hours_enabled`).
- **Indexes**:
  - `caregiver_id` (unique, sparse)
  - `elder_user_id`
  - `caregiver_user_id`
  - `is_active`

---

### 2.7 `notification_preferences`
- **Purpose**: Global notification settings for an elder user.
- **Key Fields**:
  - `user_id` (string, unique): Elder user ID.
  - `channels` (object): Enabled communication methods (`sms`, `voice`, `in_app`).
  - `quiet_hours` (object): `start_time` (e.g., `"22:00"`), `end_time` (e.g., `"07:00"`), `timezone`.
- **Indexes**:
  - `user_id` (unique)

---

### 2.8 `notifications`
- **Purpose**: Complete audit history of dispatched caregiver emergency alerts (SMS and Voice calls).
- **Key Fields**:
  - `notification_id` (string, unique): Dispatch record ID (e.g., `notif_voice_7dca05e786`).
  - `user_id` / `elder_user_id` (string): Protected elder identity.
  - `caregiver_id` (string): Target caregiver recipient.
  - `transaction_id` (string, optional): Associated transaction reference.
  - `risk_event_id` (string): Fused risk event trigger.
  - `channel` (string): `SMS` or `VOICE`.
  - `risk_level` (string): `HIGH` or `CRITICAL`.
  - `status` (string): `PENDING`, `SENDING`, `SENT`, `DELIVERED`, `FAILED`.
  - `provider_message_id` (string, optional): Twilio MessageSid or CallSid.
  - `message_preview` (string): Text excerpt of alert body.
  - `is_acknowledged` (boolean): True when caregiver has reviewed and acknowledged the alert.
  - `acknowledged_at` (string ISO, optional): Acknowledgement timestamp.
  - `acknowledged_by` (string, optional): User ID of acknowledging person.
  - `created_at` (string ISO): Dispatch timestamp.
  - `delivered_at` (string ISO, optional): Webhook delivery confirmation timestamp.
- **Indexes**:
  - `notification_id` (unique, sparse)
  - `user_id`
  - `caregiver_id`
  - `risk_event_id`
  - `transaction_id`
  - `created_at`

---

### 2.9 `revoked_tokens`
- **Purpose**: Token revocation blacklist enforcing immediate session termination on user logout.
- **Key Fields**:
  - `jti` (string, unique): Unique JWT identifier (UUIDv4).
  - `revoked_at` (datetime UTC): Timestamp of revocation.
  - `expires_at` (datetime UTC): Token expiration timestamp. Automatically monitored by MongoDB TTL background thread.
- **Indexes**:
  - `jti` (unique, sparse)
  - `expires_at` with **TTL index** (`expireAfterSeconds=0`): MongoDB actively purges expired tokens automatically, preventing table bloat.
